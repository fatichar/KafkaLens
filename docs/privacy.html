Privacy & Usage Data

What the KafkaLens desktop app sends, what it never sends, and how to turn it off.

Summary

KafkaLens sends anonymous usage data so we can see which features matter, which defaults to ship, and what breaks. It is on by default; you are told on first launch and can turn it off at any time.

  • Never sent: cluster names, broker or bootstrap addresses, topic names, partitions, consumer groups, message keys, values or headers, filter or search text, file paths, user or machine names, exception messages, plugin configuration.
  • Identifier: a random install ID generated on first launch. It is not derived from your machine or account, and you can reset it in Preferences.
  • Counts and durations are sent as coarse buckets (for example 101-500 messages, <3s), not exact values.
  • Data goes to a self-hosted Umami instance via t.kafkalens.com. It is not sold or shared. Raw events are kept for 13 months.
  • Debug builds never send anything. The code is open source: ViewModels/Telemetry.

How to turn it off

  • Choose Disable in the first-launch notice, or
  • Preferences → Privacy → untick Send anonymous usage data, or
  • set the environment variable DO_NOT_TRACK=1 or KAFKALENS_TELEMETRY=0.

When disabled, nothing is sent and any queued data on disk is deleted. Preferences → Privacy also shows every event sent in the current session.
