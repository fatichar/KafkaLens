Plugins

Extend KafkaLens with community formatters and themes — or build your own.

What plugins can do

  • Message formatters — decode payloads KafkaLens doesn't handle natively (e.g. Protobuf, Avro, proprietary binary formats). They show up in every formatter dropdown.
  • Themes — additional color themes, selectable from View → Theme.

The Plugin Manager

Open Edit → Plugin Manager…. The window has two tabs — Available and Installed — and a repository selector on top.

📷 Screenshot needed Plugin Manager: repository selector on top, Available tab listing plugins with Install buttons.

Repositories

A repository is a hosted plugins.json index of installable plugins. Use ＋ to add a repository URL, － to remove the selected one, and Refresh to reload its index. Multiple repositories can be registered; pick between them with the dropdown.

Installing

  1. Choose a repository — the Available tab lists its plugins with name, description, author, version, and a homepage link.
  2. Click Install. The button shows progress while the package downloads.
  3. A banner appears: a restart is required for plugin changes to take effect. Restart KafkaLens when convenient.

Managing installed plugins

The Installed tab lists everything on disk. Each row has an Enabled toggle (disabled plugins stay installed but don't load) and an Uninstall button. Changes take effect on restart.

Plugins live in plugins/ inside the settings directory.

Plugins run inside KafkaLens with full trust — only install plugins from sources you trust.

Developing a plugin

Plugins are .NET class libraries. Create one, reference the API packages, and ship it as a NuGet package: 

dotnet new classlib -n MyKafkaLensPlugin
<PackageReference Include="KafkaLens.Shared" Version="1.0.*" />
<PackageReference Include="KafkaLens.Formatting" Version="1.0.*" />

Match the package version to the KafkaLens major version you're targeting (e.g. 1.0.* for the 1.x line).

A message formatter

Implement IMessageFormatter and mark it with [KafkaLensExtension]: 

using KafkaLens.Formatting;
using KafkaLens.Shared.Plugins;
using System.Text;

[KafkaLensExtension(typeof(IMessageFormatter))]
public class CsvFormatter : IMessageFormatter
{
    public string Name => "CSV";

    public string? Format(byte[] data, bool prettyPrint)
        => Encoding.UTF8.GetString(data);

    public string? Format(byte[] data, string searchText, bool useObjectFilter = true)
    {
        var text = Format(data, true);
        if (text == null || string.IsNullOrEmpty(searchText))
            return text;
        // Return only lines containing the search text
        return string.Join(Environment.NewLine,
            text.Split(Environment.NewLine)
                .Where(l => l.Contains(searchText, StringComparison.OrdinalIgnoreCase)));
    }
}

Plugin lifecycle (optional)

For plugins that need initialization or cleanup, implement IKafkaLensPlugin — Initialize(IServiceProvider) runs after the app builds its service container, Shutdown() on exit: 

public class MyPlugin : IKafkaLensPlugin
{
    public void Initialize(IServiceProvider services) { /* resolve services, register extensions */ }
    public void Shutdown() { /* cleanup */ }
}

Publishing

  1. Build a package: dotnet pack -c Release
  2. Host the .nupkg somewhere reachable (static host, artifact feed, GitHub release asset).
  3. Publish a repository index (plugins.json) pointing at it:
{
  "name": "My Plugin Repository",
  "plugins": [
    {
      "id": "MyKafkaLensPlugin",
      "name": "CSV Formatter",
      "description": "Displays CSV payloads with column-aware formatting",
      "author": "You",
      "version": "1.0.0",
      "kafkalensVersion": "1.0",
      "downloadUrl": "https://example.com/MyKafkaLensPlugin.1.0.0.nupkg",
      "sha256": "<sha256 of the .nupkg, optional>",
      "homepage": "https://github.com/you/my-kafkalens-plugin"
    }
  ]
}

Users add your repository URL in the Plugin Manager and install from there. Keep plugins on net10.0 to match the app, handle malformed input gracefully, and test with large messages.
