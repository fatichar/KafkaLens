Filtering & Search

Pin down exactly the messages you need with a compact boolean syntax.

How filtering works

The Filter box above the message grid (focus it with Ctrl+F) narrows the already-fetched message list as you type — it doesn't re-query Kafka. Fetch a generous batch first, then slice it down with filters.

Matching is a case-insensitive substring test against the decoded message value. The ? button next to the box shows the same cheat sheet described here.

Syntax reference

SyntaxMeaningExample
term Message contains the text error
a && b AND — both must match error && timeout
a || b OR — either must match warning || error
!a NOT — must not match !debug
( ... ) Grouping (login || logout) && failed
"..." Exact phrase (may contain spaces and operator characters) "user not found"
a b Implicit OR — terms separated by spaces are alternatives warn error ≡ warn || error

Precedence

! binds tightest, then &&, then || (and implicit OR). So error && !debug || timeout reads as (error && !debug) || timeout. When in doubt, add parentheses.

Practical examples

Find…Filter
Errors that aren't timeoutserror && !timeout
Either of two event typesOrderCreated || OrderCancelled
A specific user doing specific things"user-42" && (login || purchase)
Any of several status codes500 502 503
An exact message"payment declined"
Everything except heartbeat noise!heartbeat

Tips

  • Filtering is instant — combine a large fetch with several quick filters rather than re-fetching for each search.
  • Terms match the decoded value, so JSON property names and values are both searchable.
  • The filter box persists per tab — switching nodes clears the list but keeps the expression for your next fetch.
  • Searching inside a single message is a different feature — the viewer's own Filter box. See Inspecting Messages.
