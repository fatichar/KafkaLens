Troubleshooting & FAQ

Diagnose issues fast — logs, shortcuts, and fixes for the common cases.

The application log

KafkaLens records what it's doing — connections, fetches, errors — in the Application Log. Open it with View → Application Log or the Log button in the status bar (which always shows the latest entry).

  • Columns: Time, Level, Source (e.g. Fetch, Startup), Message. Click headers to sort.
  • Search / Filter: the toggle switches the text box between Search (highlights matching rows) and Filter (hides non-matching rows).
  • Actions: Copy All (grab everything for a bug report), Clear, and Open Log File.

Open Log File reveals the diagnostic log written to logs/KafkaLens.log inside the settings directory — attach it to bug reports for faster diagnosis.

Common issues

Cluster won't connect (red status dot)

  • Verify the bootstrap servers — Test Connection in the Edit Clusters dialog reports the exact error; expand Show error details for the full exception.
  • Check the broker is reachable from your machine (telnet host 9092).
  • SASL/TLS clusters aren't supported by direct connections — put the gRPC backend in front of such clusters, or connect over a private network.
  • Slow networks: raise Query Topics Timeout and Admin Metadata Timeout in Preferences → Kafka.

No topics in the tree

  • Check the connection banner — the cluster may have dropped; use Connect to retry.
  • Make sure the Filter topics… box isn't hiding everything.
  • An empty topic list with a green dot usually means the cluster genuinely has no topics.

Message values look like garbage

  • The auto-detected formatter is probably wrong — change the value formatter in the Configuration tab or per-message via the Format combo. Binary formats (Protobuf, Avro) need a plugin formatter.

Fetches are slow or return nothing

  • Lower Count, or fetch a single partition instead of a whole topic.
  • Fetching from Start on a huge topic reads from the earliest retained offset — prefer End or a Timestamp near your target.
  • Raise Consume Timeout / Fetch Max Bytes in Preferences → Kafka for high-latency links.
  • Check the application log — fetch errors and counts are recorded there.

Remote (gRPC) client issues

  • Confirm the address is host:port of the backend's HTTP port (default 8080), and that the port is open through any firewall.
  • The backend only speaks HTTP/2 — a proxy in between must support h2c or gRPC pass-through.
  • Cluster list empty on the client? The backend's cluster_info.json has no clusters — register them server-side.

Update problems

  • KafkaLens checks GitHub Releases — offline machines and blocked api.github.com access make the check silently fail.
  • If the install directory isn't writable, the updater can't apply the download — reinstall to a user-writable location or run the new installer manually.
  • Help → Auto-check for Updates toggles the startup check.

Platform quirks

  • Windows SmartScreen: More info → Run anyway.
  • macOS Gatekeeper: right-click → Open, or xattr -dr com.apple.quarantine on the app.
  • Linux: a desktop session (X11/Wayland) is required; headless servers can't run the UI.

FAQ

Can KafkaLens produce messages?

No — it's a read-only browser by design. It cannot write, delete, or modify cluster data.

Does it support SASL/TLS or Schema Registry?

Not in direct connections today. For secured clusters, deploy the gRPC backend inside the cluster's network. Schema Registry support comes through formatter plugins.

Does it browse consumer groups?

No consumer-group viewer exists. KafkaLens consumes with its own group id (KafkaLens.Server by default) and, with auto-commit off (the default), doesn't disturb anyone's offsets.

Android or web versions?

Experimental targets exist in the repository but aren't shipped or supported for 1.0 — Windows, macOS, and Linux are the platforms.

Getting help

Still stuck? Open an issue on GitHub — include the diagnostic log (Open Log File) and the exact error from Test Connection if it's connectivity-related.
