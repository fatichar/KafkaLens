Browsing Messages

Navigate topics, control where fetches start, and work the message grid.

The Navigator

The left panel of an open cluster tab has two tabs of its own:

  • Topics — a tree of every topic in the cluster. Expand a topic to see its partitions. The Filter topics… box above the tree narrows the list as you type.
  • Cluster Info — the cluster's name, address, and topic count.

If the cluster is disconnected, a banner at the top of the Topics panel shows the status and a Connect button to retry.

Topic vs. partition

Select a topic to fetch across all its partitions, or a single partition to read just that partition. The fetch panel applies to whichever node is selected.

Fetching a whole topic reads from every partition — on busy topics that can be a lot of data. Prefer a specific partition when you know which one you need.

Fetch options

The right-hand Fetch panel controls where reading starts and how much to load.

From

PositionBehavior
End The most recent messages — KafkaLens reads backward from the latest offset and returns the last Count messages.
Start The earliest retained messages, reading forward.
Timestamp Pick a date and enter a time (HH:mm:ss) — fetching starts at the first message at or after that moment. The time is interpreted in your local timezone.
Offset Enter a numeric offset — fetching starts at that offset.

Fetch backwards

The Fetch backwards toggle reverses the read direction: instead of reading forward from the start position, KafkaLens reads the messages before it. It's available for Timestamp and Offset positions (for Start/End the direction is implied and the toggle is disabled).

  • Offset 5000 + backwards → the Count messages immediately before offset 5000.
  • Yesterday 18:00 + backwards → the Count messages leading up to that time.

Count

How many messages to fetch. The dropdown defaults to 10, 50, 100, 250, 500, 1000, 2500, 5000, 10000, 25000; both the list and the default selection are configurable in Preferences → Browser.

Fetching

Click Fetch Messages (or press F5 later, to repeat the same fetch). Messages stream in as they arrive — you don't wait for the whole batch before you can start reading. While a fetch is running the button becomes Stop, which cancels the fetch and keeps whatever arrived so far.

Each fetch replaces the current message list. Fetch progress and results are recorded in the application log.

The message grid

Each row shows:

ColumnContents
PartitionPartition the message came from.
OffsetMessage offset within the partition.
TimestampProducer timestamp.
KeyMessage key (decoded with the key formatter).
ValueA summary of the payload (decoded with the value formatter).
  • Sort — click a column header to sort; click again to reverse.
  • Row numbers — the narrow header column on the left numbers the rows.
  • Resize & reorder columns — drag header edges and headers.
  • Right-click a row for the context menu: Copy → Key / Value / Offset / Timestamp / All, and Save Selected / Save All (see Saving Messages).

The Configuration tab

Next to Messages in the browser is a Configuration tab. For a topic it holds its Key Formatter and Value Formatter — the decoders applied to every message — with Guess buttons that detect the format from actual data, an Apply to every cluster option, and a Save button. Partitions have no separate configuration. See formatters for details.
