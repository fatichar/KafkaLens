Connecting to Kafka

Two ways to reach your data: directly, or through a remote KafkaLens client.

Two connection types

TypeHow it worksBest for
Direct Cluster KafkaLens talks to your brokers itself using its built-in Kafka client. Local development, and clusters reachable from your machine.
KafkaLens Client KafkaLens connects to a KafkaLens gRPC backend over the network; the backend talks to Kafka. Clusters inside private networks / VPCs that you can't reach directly.

Everything is managed in one place: Cluster → Edit Clusters (Ctrl+E), which opens the Edit Clusters & Clients dialog with a tab for each type.

📷 Screenshot needed Edit Clusters & Clients dialog showing both tabs: Direct Clusters and KafkaLens Clients.

Direct clusters

In the Direct Clusters tab:

  1. Click Add (or double-click a row to Edit).
  2. Enter a Cluster Name — anything that helps you recognize it.
  3. Enter Bootstrap Servers — a single broker (localhost:9092) or a comma-separated list (kafka1:9092,kafka2:9092,kafka3:9092). Listing several brokers makes the initial connection resilient if one is down.
  4. Optionally click Test Connection to verify reachability before saving. Errors are shown in the dialog with an expandable Show error details section.
  5. Click OK, then Save in the main dialog.

Changes in this dialog are staged: nothing is written until you click Save. Click Cancel to discard everything.

Security: direct connections are plaintext — there are no SASL/TLS options. Only connect directly to clusters on trusted networks. For anything else, front the cluster with the KafkaLens gRPC backend and connect through that.

KafkaLens clients (remote backends)

A KafkaLens client is a connection to a KafkaLens backend service running near your brokers — typically inside a VPC. The clusters it can see are configured on the server, not in the desktop app.

In the KafkaLens Clients tab:

  1. Click Add.
  2. Enter a Client Name (e.g. Prod VPC), the Address of the backend (e.g. http://backend.internal:8080), and the protocol (grpc).
  3. Click OK, then Save.

Once connected, the clusters exposed by that backend appear under Cluster → Open Cluster alongside your direct ones. Deploying the backend is covered in Remote Access.

Enabling and disabling

Each cluster and client row has an Enabled checkbox. Disabled entries are hidden from Cluster → Open Cluster and any open tabs for them are closed — handy for parking a cluster that's temporarily down without deleting it.

Connection status

The dot next to each cluster or client shows its live state:

IndicatorMeaning
🟢 GreenConnected — the cluster responded to the last check.
🔴 RedDisconnected — the last check failed. Hover the dot to see the error.
⚪ GrayUnknown or disabled — no check has run yet, or the entry is disabled.
◌ SpinnerChecking — a connectivity check is in progress.

The same dot appears on open tabs and in Cluster → Open Cluster. If a tab loses its connection, a banner appears at the top of the Topics panel with a Connect button to retry.

Automatic health checks

KafkaLens re-checks connections periodically. The interval is set in Edit → Preferences → Browser → Connection Checks: Never, Every 30 seconds, Every minute, Every 5 minutes (default), Every 10 minutes, Every 15 minutes, or Every 30 minutes. Choose Never to disable automatic checks; you can still test a connection manually from the Edit Clusters dialog.

Where configuration is stored

Clusters and clients are stored as JSON in the KafkaLens data directory:

FileContents
cluster_info.jsonDirect cluster definitions.
client_info.jsonKafkaLens client definitions.

The directory is %LocalAppData%\KafkaLens on Windows, ~/.local/share/KafkaLens on Linux, and ~/Library/Application Support/KafkaLens on macOS. Click Open Settings dir… at the bottom of the Edit Clusters dialog to open it in your file manager.

Editing these JSON files by hand is supported — useful for seeding many clusters at once — but close KafkaLens first so your edits aren't overwritten on save.
